# M6 — six-stage SMOA engine

Implemented: product router, six template decomposition, date/range pre-repair,
structured dependent tools, hard stored-record verification and bounded replanning.
Four shortcuts now call the same backend source-wide engine instead of filtering
only a frontend page. Fictional demo uses public records with explicit demo routing;
private sources use a source-bound SQL snapshot. No LLM inference is simulated.

Six core templates: conflict check, mail/calendar combined query, free-time query,
daily summary, multi-step planning and simple calendar query. Product extras handle
deadlines, important mail and dated activities. Multi-intent tasks preserve dependencies.
Conflict/free-time checks include unrelated commitments, not only query-topic matches.

Default understanding is lexical rules. Optional explicit model routing uses the
existing ProcessingGateway, allowed intents and bounded JSON schema. A model cannot
choose arbitrary functions, change permissions or author unverifiable answer facts.
Answers are rendered from source records and deterministic computations. Actual
model inference remains unvalidated without a configured provider.

Time windows are half-open, source-zone aware; date-only deadlines do not occupy
intervals. Free-time requires a date and availability window; missing ranges prompt
clarification. Ambiguous/nonexistent DST clocks require explicit offset handling.
Unknown-time records are disclosed rather than interpreted as conflict-free.

Tools use at most 12 calls, three retries beyond the initial attempt for transient
failures, two replans and per-call/overall deadline checks. Replanning reruns invalid
tasks and dependent children while retaining independent successful outputs. A failed
fact check suppresses unverified content, regardless of diagnostic scores. Source reads
are bounded to 5,000 records; event-task display is further bounded and disclosed.

Returned diagnostics identify the template, stages, verification status, tool count,
processing/retrieval mode and citations. Verification means correspondence to stored
records, not proof that an extraction model interpreted the original mail correctly.
History is never used as a replacement fact source. QA text persists only when the
source's memory policy is enabled. Simple/unsafe requests do not load email bodies.

92 backend checks pass before subsequent milestones; coverage includes six templates,
tool-result dependencies, half-open intervals, Shanghai week boundaries, DST ambiguity,
missing availability, injected date errors/replanning, retry budgets, unsafe requests,
source isolation and denial of model processing on a real source with fixture provider.

The separate `legacy_route`, `legacy_datetime` and legacy weighted-quality helpers are
for labeled course-parameter experiments only. Product date rules never call the
UTC/date-midnight reproduction helper. Evaluation must not present rules/fixtures as
real model or semantic RAG results.
