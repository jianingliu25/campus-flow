# M8 — reproducible offline evaluation

Run `python scripts/manage.py evaluate`. The committed report is
`eval/reports/offline.json`; an automated check reproduces it exactly.
`eval/holdout/manifest.json` pins the SHA-256 of 40 authored intent questions before
the first evaluation. They were authored after implementation by the same project
author, so this is a held-out regression set, not an independent benchmark. No
post-evaluation intent-classification changes were made to remove the failed question.
Browser acceptance separately fixed literal DDL/recommendation labels in retrieval keywords;
intent results remain unchanged.

All predictions, denominators and the known failure remain in the JSON report.
Extraction comparisons are strict and representation-sensitive, including timestamp
offsets; they are not a complete semantic extraction benchmark. The rule fallback
is conservative and incomplete. Annotated demo events are separate public gold
records, not outputs of measured model inference.

A date-corruption injection fails hard verification with zero replans (two calls),
and passes after two configured replans (four calls, one repair used). This is a
controlled two-condition fault test, not a paper-scale ablation. Retry/pre-repair
branches have regression coverage but no separate aggregate performance claim.

Citation reference validity checks that cited IDs exist in the selected snapshot.
It does not measure human answer correctness. Product verification status and legacy
quality scores are diagnostics, not empirical answer accuracy. No real mailbox,
learned-model quality, vendor MCP schema adapter, semantic recommendation precision@5,
FAISS runtime or external generalization result is claimed.
