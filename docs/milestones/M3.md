# M3 — local EML/MBOX import

Completed on 2026-10-12. The private local import panel is separate from the
fictional three-column dashboard; integrating private mail into that dashboard is M4.

Historical M3 checkpoint: M4 now integrates imported data into the three-panel UI.
For the current first-use/source/settings workflow, see [M4](M4.md).

## Try it

Start with `python scripts/manage.py demo`, expand **导入我的本地邮件**, create a
local source with its email timezone, and choose one `.eml` or `.mbox` file.
Public, entirely fictional samples can be downloaded from the panel.

Review the preview and select messages before confirming. Unknown header dates
are visible but initially unchecked. The default mode only imports for browsing.
Select **本地规则提取** to produce date-grounded candidates without model calls.
Mail details and each candidate's source link show the normalized original text.
Repeat imports do not create extra copies within the same source.

The frozen samples have header dates on 2026-10-12; after the default 30-day scope
expires, their known-date messages will be excluded. This does not alter their dates.
The existing fixture dashboard separately shifts its fictional dates for the demo.

CLI alternatives, from the repository root:

```text
python scripts/manage.py import --file fixtures/mail/sample.eml --dry-run
python scripts/manage.py import --file fixtures/mail/sample.eml --label "Fictional practice" --mode rules
python scripts/manage.py import --directory fixtures/mail --source-id YOUR_EXISTING_LOCAL_SOURCE_ID
```

`--dry-run` parses without creating a database or source. Without `--source-id`,
each committed CLI run creates a new source; use the existing ID for deduplication.
Directory selection is explicit, flat and non-recursive. Symlinks, junctions,
reparse-point ancestors and paths outside the selected scope are rejected.

## Privacy and limits

- Browser selection sends the chosen file only to the loopback app. There is no
  directory scan, account login or automatic provider request.
- Uploads are at most 10 MiB; each message at most 1 MiB, normalized text at most
  32,000 characters, one MBOX at most 200 envelopes. CLI scope is at most 20 files
  and 10 MiB combined. Unsupported formats return bounded error codes.
- Plain MIME bodies are preferred; HTML becomes text without executing scripts,
  opening URLs, loading images or saving attachments. Original raw files are not saved.
- Previews are memory-only, expire after 10 minutes, are session/source-bound and
  one-use, and clear at shutdown. A cleanup task checks expired previews every 30 seconds.
  Limits are two previews per session, eight total and 20 MiB of normalized text.
- Default source scope is the last 30 days and 200 messages. Known dates outside
  this window are excluded; unknown dates require explicit UI selection.
- Confirmed imports store normalized data outside the repository. Body retention
  follows source policy; `retain_body=false` still permits derivative summaries,
  candidate evidence and index text. It is not a full content erasure operation.
- Cloud processing remains disabled by default. The explicit model reprocess
  button uses only the configured provider and the M2 global plus source-specific
  consent gate. Provider/API errors preserve original mail for browsing.
- Preview selection or policy errors consume the token; create a fresh preview to retry.

## Extraction behavior

The rule fallback is deliberately labeled as rules, not NLP model inference.
Fully specified dates and times are normalized to UTC using the source timezone.
Date-only deadlines retain a calendar date without inventing a midnight timestamp.
Missing years, uncertain intervals and multiple date-only alternatives stay pending.
Relative dates use the original mail Date, never the processing date. Missing or
invalid Date headers remain null; import/sorting timestamps are stored separately.
Naive Date headers use the chosen timezone with an explicit warning.

Model JSON is validated with bounded fields and exact body evidence. Dates, times
and locations must be grounded in that evidence; invalid candidates are dropped
and warnings recorded. This is a structural grounding check, not proof of semantic
correctness: negations, amendments and ambiguous language still need user review.
Timezone transitions without explicit offsets are not disambiguated by the rule
fallback. Prefer offset-bearing timestamps for DST-sensitive mail.

Upserts and indexing outbox entries commit together. Changes keep manually edited
events and flag their source as changed; obsolete machine candidates are superseded.
The durable outbox still awaits a concrete embedding/index worker in later milestones.
