# M4 — source-aware dashboard and settings

Completed on 2026-10-12. This milestone connects the three-panel design to M3 local
imports. It does not claim real mailbox connections, free-form model QA or indexing.

## Usage

Start with `python scripts/manage.py demo`. The first screen offers fictional
preview or local import. Existing local sources appear in the header selector;
the app does not automatically load their email content on page refresh.

Create a source in Settings → 来源与范围, with its email timezone. Click 导入邮件
to select an EML/MBOX file, review and confirm. The existing M3 browse/rule modes
are preserved; imported mail now appears directly in the middle panel, with
extracted candidates in the calendar panel. The pending group retains unknown dates.

Star a local-source mail to save a local flag. Opening its body marks it locally
read; detail controls can mark unread or explicitly reprocess with rules/a configured
model. These operations do not change the remote mailbox. Event detail opens its
source mail; mail detail lists linked events on the current event page.

The right panel supports four direct local queries with mail citations. Expand it
or choose 对话 for the full conversation view; returning home preserves that thread.
Source switching clears thread, input, mail/event detail and import preview. Arbitrary
questions receive an explicit unavailable message rather than fabricated model output.

## Settings and processing state

- 来源与范围 creates local sources and updates versioned read scope (1–365 days,
  up to 200 messages per local import). Scope updates revoke cloud consent and affect
  subsequent imports, not existing data. Changing a source's timezone after import
  is not exposed; create a new source for a different timezone.
- 模型 shows configuration and the processing host, with no keys or URL credentials.
  Configured does not mean connection-tested. Endpoint/key configuration remains
  server-side; no model service is contacted by opening settings.
- 隐私 saves body retention and source/provider-specific cloud consent. Consent is
  available only when a valid cloud provider is configured and globally enabled.
  Model reprocessing still requires an explicit detail action. Retention changes
  do not erase old bodies or derivative summaries/event evidence/index text.
- QA-memory/profile permissions are displayed with their unimplemented status;
  the M7 features are not simulated. Deletion/export and connector lifecycle await
  later milestones, with no destructive placeholder actions.
- The header/status row shows last local import and actual outbox counts. It does
  not report a successful sync or indexing progress when no connector/worker exists.

## Data boundaries

`GET /api/dashboard` returns a SQLite read snapshot for the explicitly active
workspace/source. Body text is omitted; summaries and candidate evidence may contain
mail content. Source-wide statistics accompany independent 50-item mail/event pages.
Page navigation never silently truncates the source total. Filters, shortcuts,
recommendation lists and linked-event lists operate on the currently loaded pages,
and the interface labels this scope. Pagination may shift when new data is imported.

Scoped flag writes require local session, same-origin, CSRF and matching source
selection. Flag changes do not revise mail content or enqueue duplicate index work.
Private requests bind to the initiating source ID; the server rejects stale source
headers. Switching/deactivating a source clears its session's memory previews.
The existing database schema remains at 0002; no migration is necessary for M4.

The UI stores no mail/body/chat/source selection in localStorage or sessionStorage.
Refresh returns to explicit source choice. Browser memory and the local database are
not encryption or full data erasure claims. Keep the app on loopback.
