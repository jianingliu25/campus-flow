# M5 — read-only connectors (offline acceptance)

The user chose offline acceptance first and asked for MCP-service research. IMAPS,
Streamable HTTP MCP, session/system credentials, manual bounded sync, durable cursor
checkpoints, pause and disconnect are implemented. No real mailbox was authorized.

80 backend tests pass locally on Windows, including read-only IMAP command checks,
UIDVALIDITY reset, size/scope bounds, MCP JSON/SSE/session handling, tool whitelist,
schema/address checks, native Windows vault roundtrip, credentials redaction,
scoped job visibility, cancellation before persistence and policy changes in flight.
The authored MCP fixture server is tested end-to-end through HTTP ASGI transport.
This is offline protocol evidence, not third-party account compatibility proof.

See [connector tutorial and compatibility matrix](../connectors.md). The first MCP
adapter requires a normalized mail contract. Composio Gmail/Outlook and a self-hosted
Gmail MCP project were researched from their primary documentation; vendor mappings
and OAuth remain explicit limitations. A protocol connection alone is not mail-schema
or account verification. The supplied fictional MCP service requires no real account.

Remaining validation: provider-authorized real IMAP and MCP mail, OAuth refresh,
vendor-specific schema/header adapters and platform secure vaults beyond Windows.
These remain documented external acceptance gaps, not reasons to stop M6–M9 engineering.
